# Project Defensibility Guide

| Project | Safe claim | Do not claim | Likely follow-up | Code to know deeply | Finance / AI depth |
| --- | --- | --- | --- | --- | --- |
| P1 | Built evidence-linked document RAG with deterministic evaluation | Production OCR or broad real-document accuracy | How do you verify citation support? | ingestion, chunking, retrieval, citations, gates | Statements and sources / semantic RAG |
| P2 | Built explainable deterministic screening with checkpointed review | Comprehensive live sourcing or unbiased ranking | Why this scoring model? | thesis, screening, ranking, workflow | Acquisition criteria / ranking evaluation |
| P3 | Built auditable offline trading comps | Live banker-grade valuation or implicit FX | How do you prevent basis mismatch? | financial models, multiples, valuation | EV/equity, LTM/NTM / deterministic contracts |
| P4 | Built evidence-grounded precedent valuation and review | Complete deal database or legal interpretation | How do you distinguish deal-value bases? | verification, selection, multiples, workflow | Control and deal value / extraction-conflict handling |
| P5 | Built synthetic-VDR diligence with deterministic finance | Full legal/tax/cyber diligence or autonomous QoE | How do you validate add-backs? | financial analytics, specialists, reporting | QoE/NWC/net debt / evidence-linked agents |
| P6 | Built typed orchestration and native-local specialist composition | One live end-to-end deal or production multi-agent platform | Why adapters and canonical state? | adapters, planning, graph, reconciliation, synthesis | Reconciliation / LangGraph and HITL |

Across all projects, state the evaluation dataset and runtime mode whenever quoting a metric.
Describe limitations before the interviewer has to discover them. Be able to hand-calculate at
least one P3 multiple/range, the public P4 multiple, and the P5 EBITDA/NWC/net-debt fixtures.
